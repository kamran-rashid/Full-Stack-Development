## 4. Part C: challenges

**C1: Stateful flow without JavaScript (claimed).** The calculator is a four-step flow: amount, yearly return, years, compounding. Each step is a radio group; `:has()` writes `--P`, `--r`, `--t`, `--cmp`; one `calc()` with `pow()` gives A = P·(1 + r/n)^(n·t); counters print the rupees (with Indian digit grouping) and the sentence, the "× your money" figure, and the bar chart update. The glossary opens with a native `popover` and a `<form method="dialog">` stops Enter from reloading the page. A `type="reset"` button returns the ledger to defaults. No `<script>`, no inline handlers.

**C2: Designed print stylesheet (claimed).** `@page { size: A4 }`; a statement letterhead (`.print-head`) appears only in print; navigation, decoration, video, controls and animations are removed; every figure is printed as a number; unselected options disappear so only the chosen amount shows; URLs are printed after links with `attr(href)` and abbreviations with `attr(title)`; chart colours are forced with `print-color-adjust: exact`; rows, cards and charts do not split across pages. The result is a 7-page A4 PDF (`evidence/08-print-statement.pdf`), longer than I would like.

**Also built (not claimed):** C3 (reduced motion and high contrast are designed, not just switched off: rows C7 and C9) and C4 (two captioned speakers in different colours and screen positions).
Not attempted: C5, C6.

## 5. How the no-JavaScript engine works
1. Radios named `b1..b7` (budget) and `s1..s7` (spent) and `amount`, `rate`, `years`, `frequency` hold the state.
2. `body:has(#b3-2:checked)` sets `--B3: 4000`; the totals are sums of those variables; `@property` types them as numbers so that `calc()` results are real numbers.
3. `@container style(--is-over: 1)` turns numeric results into states (over/under, any over, deficit).
4. `.inr` is a rupee formatter: four empty `<i>` elements print the crore, lakh, thousand and hundred groups using `counter()`; style queries show a group only when the number is big enough.
5. Numbers of seven digits or more lose precision when passed through `var()` (browsers print `1.55292e+06`), so the calculator passes them in two exact halves (thousands and remainder).

## 8. Browser notes (Chrome is the reference)
I tested in Chromium only. From browser documentation, not from my own test, the places where Firefox or Safari may differ:
- `@container style(--x: 1)` on custom properties is the core of the status text and number grouping. Support outside Chrome/Edge is newer or missing (check current compatibility tables). Where it fails, numbers show without commas and over/under words may not switch.
- `animation-timeline: view()` (scroll reveals) is not in every browser; it is behind `@supports`, so those browsers show the content without the animation.
- `::cue` selectors (`v[voice]`, classes) are supported unevenly outside Chrome.
- `:has()`, `pow()`, `round()`, `mod()`, `@property` and `popover` are in current Firefox and Safari but older versions lack them.

## 9. Limitations
- **Screen readers:** the values drawn by CSS counters are not exposed in Chrome's accessibility tree (I checked with Playwright's accessibility snapshot). The choices (radio buttons and their labels), the "▲ Over budget" words and the static sentences are accessible, but the computed totals are not announced. A page like this should have a real `<output>` fed by JavaScript; that is forbidden here.
- **Choices instead of typing:** amounts are steps, not free numbers.
- **Print is 7 pages**, not a 1–2 page statement.
- **Floating point:** CSS uses single-precision numbers; results of 8 digits can be off by a few rupees.
- Only Chromium was tested.
